# Contributing

Open an issue for architectural changes. Use a branch, keep modules backward compatible, update examples and documentation, and submit the PR template in full. Run `make fmt`, `make validate`, `make lint`, and `make security`. Never commit state, plans, credentials, backend files, private tfvars, kubeconfig, or secret values. Production changes require two reviewers, a reviewed plan, an owner, a maintenance window, and rollback steps. Use Conventional Commits where practical.
